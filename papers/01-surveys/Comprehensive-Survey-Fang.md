# A Comprehensive Survey of Self-Evolving AI Agents: A New Paradigm Bridging Foundation Models and Lifelong Agentic Systems

## 基本信息

- **作者**: Jinyuan Fang 等
- **机构**: 格拉斯哥大学（领衔）、谢菲尔德大学、穆罕默德·本·扎耶德人工智能大学、新加坡国立大学、剑桥大学、伦敦大学学院、阿伯丁大学、莱顿大学
- **发表会议**: arXiv 预印本（2025）
- **论文链接**: https://arxiv.org/abs/2508.07407
- **代码链接**: 未提供（综述论文）
- **关键词**: Self-Evolving AI Agents, Foundation Models, Lifelong Learning, Optimisers, Feedback Loop
- **摘要**: 大语言模型的最新进展激发了人们对能够解决复杂真实世界任务的 AI 智能体的浓厚兴趣。然而，大多数现有智能体系统依赖人工设计的配置，部署后保持静态，限制了其适应动态演变环境的能力。为此，近期研究探索了智能体进化技术，旨在基于交互数据和环境反馈自动增强智能体系统。这一新兴方向为自进化 AI 智能体奠定了基础，将基础模型的静态能力与终身智能体系统所需的持续适应性桥接起来。在本综述中，我们全面回顾了现有的自进化智能体系统技术。首先，我们引入一个统一的概念框架，抽象出自进化智能体系统设计背后的反馈循环。该框架强调四个关键组件：**系统输入（System Inputs）、智能体系统（Agent System）、环境（Environment）和优化器（Optimisers）**，作为理解和比较不同策略的基础。基于该框架，我们系统回顾了针对智能体系统不同组件的大量自进化技术。我们还研究了为生物医学、编程和金融等专业领域开发的领域特定进化策略，其中优化目标与领域约束紧密耦合。此外，我们专门讨论了自进化智能体系统的评测、安全与伦理考量。
- **TLDR 太长不想读**: 第二篇重要的自进化 Agent 综述。它提出一个统一反馈循环框架（输入→智能体→环境→优化器），把所有自进化技术统一为"用什么优化器、基于什么反馈、更新智能体哪个组件"。相比 Gao et al. 的 what/when/how，本文更强调**优化器视角**和**领域特定进化**（医疗/编程/金融），并专设评测、安全、伦理章节。

## Q1: 这篇论文试图解决什么问题？（按照引言逻辑）

**背景**：LLM 驱动的智能体被寄予厚望解决复杂现实任务。

**痛点**：现有系统多为**人工配置 + 部署后静态**，无法适应动态环境；而真实部署需要终身适应能力。

**缺口**：自进化技术零散分布在不同子领域，缺乏统一的抽象来比较"谁在优化什么、基于什么反馈、优化目标是什么"。

**本文贡献**：
1. 提出统一概念框架（System Inputs / Agent System / Environment / Optimisers）；
2. 基于该框架系统回顾各组件进化技术；
3. 覆盖领域特定进化策略（生物医学/编程/金融）；
4. 专门讨论评测、安全与伦理。

## Q2: 有哪些相关研究？

- **AutoML / 神经架构搜索**：自动优化模型，但多限于超参数；
- **提示优化（Prompt Optimization）**：如 APE、OPRO，优化文本指令；
- **持续学习 / 终身学习**：解决灾难性遗忘；
- **强化学习智能体**：从环境奖励学习策略；
- **多智能体系统**：角色协作；
- 与 Gao et al. 综述互补，后者偏 what/when/how，本文偏优化器与领域应用。

## Q3: 论文如何解决这个问题？（核心框架解释）

本文的核心是**四组件反馈循环抽象**：

1. **System Inputs（系统输入）**：智能体接收的任务、上下文、用户指令；
2. **Agent System（智能体系统）**：被优化的对象——模型、记忆、工具、提示、工作流、多智能体拓扑；
3. **Environment（环境）**：提供反馈的来源——代码执行器、游戏引擎、Web 环境、人类反馈；
4. **Optimisers（优化器）**：执行进化的算法——梯度下降、RL、进化算法、LLM 自反思、文本梯度。

**为什么用这个框架**：因为它把"进化"拆解为可独立设计的四个环节。任何自进化方法都可以回答四个问题：(1) 输入是什么？(2) 优化系统哪个部分？(3) 反馈从哪来？(4) 用什么优化器？这使得跨方法比较变得清晰。

**领域特定进化的意义**：在医疗中优化目标含安全性约束，在编程中可依赖执行反馈，在金融中需满足合规——优化器必须与领域约束耦合。

## Q4: 论文使用的训练数据/结构细节/来源等详细信息

综述论文，无新训练。文献来源为 2023–2025 年间的自进化智能体相关工作。作者按四组件框架归类，并单独整理了领域特定工作。

## Q5: 论文做了哪些实验？

无新实验。其贡献是**分类学与对比分析**：把不同方法放入统一框架，比较其优化器类型、反馈来源与目标组件，并汇总评测基准与安全/伦理考量。

## Q6: 这篇论文的创新点和可以借鉴的地方

- **创新点**：四组件反馈循环抽象，特别是把 **Optimisers** 显式独立出来作为一类研究对象。
- **可借鉴**：
  1. 设计新自进化方法时，明确回答"优化器是什么、反馈从哪来"；
  2. 领域特定进化提示：通用方法迁移到垂直领域需重新定义优化目标；
  3. 评测与安全章节可作为设计 checklist。

## Q7: 这篇论文有哪些不足

- 与 Gao et al. 综述在覆盖范围上高度重叠，区分度有限；
- 四组件框架对"进化动力学"（如收敛性、坍塌）的数学刻画不足；
- 领域覆盖虽广但深度有限，各领域仅点到为止。

## Q8: 提炼论文的一般技术和逻辑范式

**范式**：自进化智能体 = `Optimiser(Agent System, Environment Feedback) → Updated Agent System`

关键是**反馈循环的闭合程度**：
- 开环：人类提供反馈；
- 半闭环：环境自动反馈 + 人类监督；
- 全闭环：智能体自生成反馈（如自奖励）。

这为理解后续论文（R-Zero 全闭环、R-Few 半闭环）提供了坐标。

## Q9: 针对这篇文章，思考有哪些值得做的研究话题

### 研究主题

- **上位类**：终身智能体系统（Lifelong Agentic Systems）
- **下位类**：优化器设计、领域特定进化、反馈循环闭合度
- **同位类**：AutoML、RL、进化计算

### 数据类型
- 交互数据、环境反馈、领域约束数据（医疗记录/代码/金融时序）

### 研究设计
1. **优化器对比研究**：在同一智能体系统上系统比较不同优化器（RL vs 进化 vs LLM 自反思）的效果与成本；
2. **领域迁移**：研究通用自进化方法迁移到医疗/金融时的失效模式与适配策略；
3. **闭环程度-风险曲线**：量化"闭环程度"与"误进化风险"的关系。
