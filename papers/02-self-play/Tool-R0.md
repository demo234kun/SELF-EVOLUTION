# Tool-R0: Self-Evolving LLM Agents for Tool-Learning from Zero Data

## 基本信息

- **作者**: Emre Can Acikgoz 等
- **机构**: 未公开（arXiv 预印本）
- **发表会议**: arXiv 预印本（2026）
- **论文链接**: https://arxiv.org/abs/2602.21320
- **代码链接**: 未提供
- **关键词**: Tool-Learning, Self-Play RL, Zero-Data, Generator-Solver, Co-Evolution
- **摘要**: 大语言模型（LLM）正成为能够使用工具解决复杂任务的自主智能体的基础。强化学习（RL）已成为注入此类智能体能力的常用方法，但通常在严格控制的环境下进行。它往往依赖精心构造的任务-解决方案对和大量人工监督，这为通向超级智能系统的开放式自进化制造了根本障碍。在本文中，我们提出 **Tool-R0** 框架，用于在零数据假设下通过自对弈 RL 从零开始训练通用工具调用智能体。从同一个基座 LLM 初始化，Tool-R0 共同进化一个 **Generator** 和一个 **Solver**，二者具有互补奖励：一个提出针对另一个能力前沿的定向挑战性任务，另一个学习用真实世界工具调用来解决它们。这创造了一个无需任何预存任务或数据集的自我进化循环。在不同工具使用基准上的评估表明，Tool-R0 相对基座模型产生了 **92.5% 的相对提升**，并在相同设置下超越了完全监督的工具调用基线。我们的工作进一步通过分析共进化、课程动力学和扩展行为，为自对弈 LLM 智能体提供了经验性洞见。
- **TLDR 太长不想读**: Tool-R0 把零数据自对弈从"推理"扩展到"工具调用"。Generator 和 Solver 从同一基座模型出发共进化：Generator 在 Solver 能力前沿出题，Solver 学习用真实工具调用解题。完全不需要预存任务或数据集，相对基座模型提升 92.5%，还超过了全监督基线。它证明了自对弈 RL 可以训练复杂的 agentic 能力（工具使用），而不仅是纯推理。

## Q1: 这篇论文试图解决什么问题？（按照引言逻辑）

**背景**：LLM 正成为使用工具的自主智能体；RL 是注入工具调用能力的主流方法。

**痛点**：现有 RL 工具训练**依赖精心构造的任务-解对和大量人工监督**，且常在严格控制环境下进行——这与"开放式自进化"的目标矛盾。

**缺口**：能否在**零数据**假设下，通过自对弈 RL 从零训练通用工具调用智能体？

**本文贡献**：提出 Tool-R0，Generator-Solver 共进化框架，无需预存任务/数据集即可训练工具调用能力。

## Q2: 有哪些相关研究？

- **工具学习**：Toolformer、ToolLLM（依赖监督数据）；
- **自对弈 RL**：R-Zero、MAE（偏推理，无真实工具）；
- **Agentic RL**：在环境中学习工具使用；
- **零数据训练**：合成数据、自博弈。

Tool-R0 的独特之处：**把自对弈与真实工具调用结合**，实现工具能力的零数据自进化。

## Q3: 论文如何解决这个问题？（核心框架解释）

**核心机制：Generator-Solver 互补奖励共进化**

1. **Generator（出题者）**：
   - 提出针对 Solver **能力前沿**的挑战性任务；
   - **奖励**：任务应恰好处于 Solver 能力边界（可解但困难）。

2. **Solver（解题者）**：
   - 学习用**真实世界工具调用**解决任务；
   - **奖励**：任务解决成功。

**为什么是"互补奖励"**：Generator 的奖励来自"难住 Solver 的程度"，Solver 的奖励来自"解决问题"。二者形成对抗-协作动态，自动生成难度匹配的课程。

**为什么用真实工具**：与纯文本推理不同，工具调用提供**可验证的执行结果**（工具返回值），这属于验证层级中的"执行验证"，信号强、可靠。

**关键优势**：无需任何预存任务或数据集——完全从同一基座模型出发。

## Q4: 论文使用的训练数据/结构细节/来源等详细信息（可复现目标）

- **数据**：零数据假设——无预存任务或数据集；
- **初始化**：同一基座 LLM 复制为 Generator 和 Solver；
- **工具**：真实世界工具（具体工具集未在摘要详述）；
- **训练**：自对弈 RL，互补奖励。

## Q5: 论文做了哪些实验？

- **结果**：相对基座模型 **92.5% 相对提升**；
- **对比**：在相同设置下**超越完全监督的工具调用基线**；
- **分析**：共进化动力学、课程动态、扩展行为。

## Q6: 这篇论文的创新点和可以借鉴的地方

- **创新点**：把零数据自对弈扩展到工具学习；互补奖励设计；真实工具调用作为强验证信号。
- **可借鉴**：
  1. 工具调用任务天然提供执行验证，是自进化的理想场景；
  2. 互补奖励（出题 vs 解题）可推广到其他能力训练；
  3. 课程动力学分析可用于诊断训练停滞。

## Q7: 这篇论文有哪些不足

- 工具集的具体范围与泛化性未充分说明；
- 真实工具调用有**成本/延迟/安全**问题（如 API 调用失败、危险操作）；
- 与全监督基线的对比设置细节不足；
- 长期自进化的稳定性未验证。

## Q8: 提炼论文的一般技术和逻辑范式

**范式**：`Zero-Data Self-Play for Tool Learning`

```
基座LLM → Generator(出题,能力前沿奖励) + Solver(工具调用解题)
   → 互补奖励共进化 → 通用工具调用智能体
```

关键：**真实工具提供执行级验证**，使工具能力比纯开放域更容易自进化。

## Q9: 针对这篇文章，思考有哪些值得做的研究话题

### 研究主题

- **上位类**：零数据 agentic 能力自进化
- **下位类**：工具合成、工具选择、调用可靠性、成本约束
- **同位类**：R-Zero、Agent0、工具学习

### 数据类型
- 自生成工具调用任务、真实工具执行轨迹

### 研究设计
1. **成本感知自对弈**：在奖励中加入调用成本/延迟，训练高效工具使用；
2. **工具合成进化**：让 Generator 不仅出题还合成新工具（与 Agent0 呼应）；
3. **安全工具调用**：研究如何避免自进化中学到危险工具操作（与 Misevolution 呼应）。
