# MLEvolve: A Self-Evolving Framework for Automated Machine Learning Algorithm Discovery

## 基本信息

- **作者**: Shangheng Du 等
- **机构**: 中国科学院等（多机构合作）
- **发表会议**: arXiv 预印本（2026）
- **论文链接**: https://arxiv.org/abs/2606.06473
- **代码链接**: https://github.com/InternScience/MLEvolve
- **关键词**: ML Engineering, Progressive MCGS, Retrospective Memory, Cross-Branch Information Flow, MLE-Bench
- **摘要**: 大语言模型（LLM）智能体越来越多地应用于长视野任务，如科学发现和机器学习工程（MLE），其中**持续自进化**成为关键能力。然而，现有 MLE 智能体遭受**分支间信息隔离（inter-branch information isolation）、无记忆搜索（memoryless search）和缺乏层级控制**的问题，共同阻碍了长视野优化。我们提出 **MLEvolve**，一个基于 LLM 的自进化多智能体框架，用于端到端的机器学习算法发现。通过将树搜索扩展为 **Progressive MCGS（渐进式蒙特卡洛图搜索）**，MLEvolve 通过基于图的参考边实现**跨分支信息流**，并通过熵启发的渐进调度逐渐将搜索从广泛探索转向聚焦利用。为让智能体从累积经验中进化，我们引入**回顾性记忆（Retrospective Memory）**，结合冷启动领域知识库和用于任务特定经验检索与复用的动态全局记忆。为稳定长视野迭代，我们进一步通过自适应编码模式将战略规划与代码生成解耦。在 **MLE-Bench** 上的评估表明，MLEvolve 在 12 小时预算（标准运行时间的一半）下在多个维度（包括平均奖牌率和有效提交率）上取得最先进性能。此外，MLEvolve 在数学算法优化任务上也超越了包括 AlphaEvolve 在内的专门算法发现方法，展示了强跨域泛化能力。
- **TLDR 太长不想读**: MLEvolve 解决 MLE 智能体的三个痛点：**分支间信息隔离、无记忆搜索、缺乏层级控制**。方案：(1) **Progressive MCGS**——图参考边实现跨分支信息流，熵驱动调度从探索转向利用；(2) **回顾性记忆**——冷启动知识库 + 动态全局记忆；(3) **规划与代码生成解耦**。在 MLE-Bench 上 12 小时（标准一半）达 SOTA，还超越 AlphaEvolve。核心：**让搜索有记忆、有信息流、有层级**。

## Q1: 这篇论文试图解决什么问题？（按照引言逻辑）

**背景**：LLM Agent 用于长视野任务（科学发现、MLE），持续自进化是关键能力。

**痛点**：现有 MLE 智能体有三个问题：
1. **分支间信息隔离**——不同搜索分支互不交流；
2. **无记忆搜索**——不积累经验；
3. **缺乏层级控制**——规划与执行混乱。

**缺口**：如何设计能长期有效进化的 MLE 智能体？

**本文贡献**：MLEvolve，Progressive MCGS + 回顾性记忆 + 规划-生成解耦。

## Q2: 有哪些相关研究？

- **MLE Agent**：AIDE、MLAgentBench；
- **AlphaEvolve**：算法发现；
- **树搜索 / MCTS**：蒙特卡洛树搜索；
- **记忆系统**：经验检索；
- **MLE-Bench**：ML 工程基准。

## Q3: 论文如何解决这个问题？（核心框架解释）

**核心机制：三个关键组件**

1. **Progressive MCGS（渐进式蒙特卡洛图搜索）**：
   - 把树搜索扩展为**图搜索**：通过**基于图的参考边（reference edges）**实现**跨分支信息流**；
   - **解决**：分支间信息隔离——不同分支可以互相参考；
   - **熵启发的渐进调度**：逐渐从**广泛探索（exploration）**转向**聚焦利用（exploitation）**；
   - **为什么**：早期需要广探索找到好方向，后期需要聚焦优化。

2. **回顾性记忆（Retrospective Memory）**：
   - **冷启动领域知识库**（先验知识）+ **动态全局记忆**（任务特定经验）；
   - **解决**：无记忆搜索——智能体可检索和复用经验；
   - **为什么**：长视野任务需要积累经验，避免重复犯错。

3. **战略规划与代码生成解耦（Adaptive Coding Modes）**：
   - 通过自适应编码模式分离**战略规划**与**代码生成**；
   - **解决**：缺乏层级控制；
   - **为什么**：规划需要全局视角，代码生成需要局部细节，解耦后各自优化。

**结果**：
- MLE-Bench 上 **12 小时**（标准运行时间的一半）达 SOTA（平均奖牌率、有效提交率）；
- 在数学算法优化上**超越 AlphaEvolve**，展示跨域泛化。

## Q6: 这篇论文的创新点和可以借鉴的地方

- **创新点**：Progressive MCGS（跨分支信息流 + 熵调度）；回顾性记忆；规划-生成解耦。
- **可借鉴**：
  1. **跨分支信息流**避免重复探索；
  2. **熵驱动调度**平衡探索与利用；
  3. **冷启动 + 动态记忆**的双层记忆设计；
  4. 规划与生成解耦提升稳定性。

## Q7: 这篇论文有哪些不足

- 系统复杂，组件众多，调参困难；
- 计算成本高（长视野搜索）；
- 记忆可能引入噪声；
- 主要在 MLE-Bench 验证。

## Q8: 提炼论文的一般技术和逻辑范式

**范式**：`Memory-Augmented Graph Search for MLE`

```
冷启动知识 + 动态记忆 → Progressive MCGS(跨分支信息流+熵调度)
   → 规划/生成解耦 → SOTA ML算法
```

核心：**长视野搜索需要记忆、信息流和层级控制**三要素。
