# Darwin Gödel Machine: Open-Ended Evolution of Self-Improving Agents

## 基本信息

- **作者**: Jenny Zhang 等
- **机构**: 不列颠哥伦比亚大学（UBC）、Vector Institute、Sakana AI
- **发表会议**: arXiv 预印本（2025）
- **论文链接**: https://arxiv.org/abs/2505.22954
- **代码链接**: https://github.com/jennyzzt/dgm
- **关键词**: Self-Improving, Open-Ended Evolution, Code Evolution, Gödel Machine, Coding Agent
- **摘要**: 当今大多数 AI 系统受限于人工设计的固定架构，无法自主且持续地自我改进。另一方面，科学方法提供了一个累积的、开放式的系统，每个创新都建立在先前的制品之上，从而实现未来的发现。人们越来越希望当前推进 AI 的人工过程本身可以自动化。如果安全地完成，这种自动化将加速 AI 发展，使我们更快收获其益处。这一前景提出了一个问题：AI 系统如何能在变得更好解决相关问题的同时，无休止地改进自身？先前的方法（如元学习）提供了自动发现新算法的工具集，但受限于人工设计的合适搜索空间和一阶改进。另一方面，Gödel machine 引入了一种理论上的自我改进 AI 方法，能够以可证明有益的方式修改自身。遗憾的是，其原始公式在实践中不可能创建，因为无法证明大多数自我修改的影响。为解决这一限制，我们提出 **Darwin Gödel Machine（DGM）**，一个新颖的自我改进系统，迭代地修改自身代码（从而也改进其修改自身代码库的能力），并使用编码基准经验性地验证每次变更。在本文中，DGM 旨在优化由冻结基础模型驱动的编码智能体的设计，这些智能体能够通过工具使用读取、写入和执行代码。受生物进化和开放性研究的启发，DGM 维护一个生成编码智能体的**档案（archive）**。它从档案中采样，并尝试创建被采样智能体的新的、有趣的、改进的版本。这种开放式探索形成一棵不断增长的、多样化的高质量智能体树，允许并行探索搜索空间中的许多不同路径。经验上，DGM 自动改进其编码能力（如更好的代码编辑工具、长上下文窗口管理、同行评审机制），在 **SWE-bench 上从 20.0% 提升到 50.0%**，在 **Polyglot 上从 14.2% 提升到 30.7%**。此外，DGM 显著优于没有自我改进或开放式探索的基线。所有实验都在安全预防措施下进行（如沙箱、人类监督）。总体而言，DGM 代表了迈向自我改进 AI 的重要一步。
- **TLDR 太长不想读**: DGM 是自我改进 AI 的里程碑（209 引用）。它把 Gödel machine 的"可证明有益的自我修改"替换为"**经验验证的自我修改**"——迭代修改自身代码，用编码基准验证每次变更。受生物进化启发，维护一个智能体**档案**，采样并创建改进版本，形成开放式探索的智能体树。SWE-bench 从 20.0% → 50.0%，Polyglot 14.2% → 30.7%。核心：**用经验验证替代理论证明，实现开放式的代码自进化**。

## Q1: 这篇论文试图解决什么问题？（按照引言逻辑）

**背景**：AI 系统受限于人工设计的固定架构，无法自主持续自我改进；科学方法则是累积、开放式的。

**痛点**：希望自动化"推进 AI 的过程"，但：
- **元学习**：受限于人工设计的搜索空间和一阶改进；
- **Gödel machine**：理论上可证明有益，但**实践中无法证明大多数自我修改的影响**。

**缺口**：如何实现**可实践**的开放式自我改进？

**本文贡献**：DGM，用经验验证替代理论证明，实现开放式的代码自进化。

## Q2: 有哪些相关研究？

- **Gödel Machine**：理论自改进（不可实践）；
- **元学习**：自动发现算法（受限于搜索空间）；
- **开放性研究（Open-Endedness）**：持续创新；
- **进化算法**：变异、选择、档案；
- **编码 Agent**：SWE-bench 上的 Agent。

## Q3: 论文如何解决这个问题？（核心框架解释）

**核心机制：经验验证的开放式进化**

**关键转变**：Gödel machine 要求"**可证明有益**"的自我修改 → DGM 改为"**经验验证**"的自我修改（在编码基准上验证）。

**框架组成**：
1. **冻结基础模型（Frozen Foundation Model）**：驱动编码 Agent 的 LLM 固定不变（安全性）；
2. **编码 Agent**：能通过工具使用读取、写入、执行代码；
3. **档案（Archive）**：维护所有生成的编码智能体；
4. **开放式探索**：
   - 从档案采样一个智能体；
   - 尝试创建**新的、有趣的、改进的**版本；
   - 形成**不断增长的、多样化的高质量智能体树**；
   - 允许并行探索搜索空间的多条路径。

**为什么是"Darwin"**：受**生物进化**启发——变异（改代码）+ 选择（基准验证）+ 档案（种群）。同时受**开放性研究**启发——持续产生新颖性。

**自我改进的递归性**：DGM 不仅改进编码能力，还**改进其修改自身代码的能力**（元改进）。

**实验结果**：
- 自动改进出：更好的代码编辑工具、长上下文窗口管理、同行评审机制；
- **SWE-bench: 20.0% → 50.0%**；
- **Polyglot: 14.2% → 30.7%**；
- 显著优于无自我改进/无开放探索的基线。

**安全措施**：沙箱、人类监督。

## Q4: 论文使用的训练数据/结构细节/来源等详细信息（可复现目标）

- **基础模型**：冻结的 LLM（不更新权重）；
- **基准**：SWE-bench（软件工程）、Polyglot（多语言代码）；
- **档案**：所有生成的 Agent 版本；
- **安全**：沙箱 + 人类监督；
- **代码**：https://github.com/jennyzzt/dgm

## Q5: 论文做了哪些实验？

- **SWE-bench**：20.0% → **50.0%**；
- **Polyglot**：14.2% → **30.7%**；
- **对比**：显著优于无自我改进/无开放探索基线；
- **发现**：自动改进出代码编辑工具、上下文管理、同行评审机制。

## Q6: 这篇论文的创新点和可以借鉴的地方

- **创新点**：用经验验证替代理论证明，使自改进可实践；档案式开放式探索；递归自我改进。
- **可借鉴**：
  1. **经验验证 > 理论证明**——务实的自改进路径；
  2. **档案 + 采样 + 变异**是开放探索的有效结构；
  3. 冻结基础模型 + 进化 harness 的安全设计。

## Q7: 这篇论文有哪些不足

- 依赖编码基准作为唯一验证信号（验证层级受限）；
- 开放式探索的算力成本高；
- 自我修改可能引入难以察觉的缺陷；
- 安全性依赖外部沙箱/监督，非内生保证。

## Q8: 提炼论文的一般技术和逻辑范式

**范式**：`Empirically-Validated Open-Ended Self-Improvement`

```
档案(Agent种群) → 采样 → 变异(改代码) → 基准验证 → 加入档案
   → 开放式探索 → 递归自我改进
```

核心：**把"自我修改"从理论证明问题转为经验验证问题**，用进化结构实现开放式探索。

## Q9: 针对这篇文章，思考有哪些值得做的研究话题

### 研究主题

- **上位类**：开放式自我改进 AI
- **下位类**：验证信号设计、档案管理、递归改进、安全约束
- **同位类**：Gödel Machine、进化计算、神经架构搜索

### 数据类型
- 代码版本、基准评测、Agent 档案

### 研究设计
1. **更强验证**：引入形式化验证弥补基准验证的不足；
2. **效率优化**：降低开放式探索的算力成本；
3. **内生安全**：设计不依赖外部监督的自我修改安全保证。
