# Agent0: Unleashing Self-Evolving Agents from Zero Data via Tool-Integrated Reasoning

## 基本信息

- **作者**: Peng Xia 等
- **机构**: 未公开（arXiv 预印本，疑似 UNC / 多机构）
- **发表会议**: arXiv 预印本（2025）
- **论文链接**: https://arxiv.org/abs/2511.16043
- **代码链接**: https://github.com/aiming-lab/Agent0
- **关键词**: Zero-Data, Multi-Step Co-Evolution, Tool Integration, Curriculum Agent, Executor Agent
- **摘要**: 大语言模型（LLM）智能体，通常用强化学习（RL）训练，受限于对人工整理数据的依赖，限制了可扩展性并使 AI 受缚于人类知识。现有的自进化框架提供了替代方案，但通常受限于模型固有能力和单轮交互，阻碍了涉及工具使用或动态推理的复杂课程的发展。我们提出 **Agent0**，一个完全自主的框架，通过**多步共进化和无缝工具集成**，在无外部数据的情况下进化出高性能智能体。Agent0 在从同一基座 LLM 初始化的两个智能体之间建立**共生竞争**：一个 **Curriculum Agent（课程智能体）**提出越来越难的前沿任务，一个 **Executor Agent（执行智能体）**学习解决它们。我们集成外部工具以增强执行智能体的问题解决能力；这一提升反过来迫使课程智能体构建更复杂的、工具感知的任务。通过这一迭代过程，Agent0 建立了持续产生高质量课程的自我强化循环。经验上，Agent0 大幅提升推理能力，将 Qwen3-8B-Base 在数学推理上提升 18%，在通用推理基准上提升 24%。
- **TLDR 太长不想读**: Agent0 把"零数据自进化"升级为"**多步 + 工具集成**"。Curriculum Agent 出越来越难的前沿任务，Executor Agent 学习解决，并且**集成外部工具**。工具让 Executor 更强，反过来逼迫 Curriculum 出更复杂的工具感知任务——形成自我强化循环。Qwen3-8B 数学 +18%、通用推理 +24%。关键升级：从单轮推理扩展到多步工具使用。

## Q1: 这篇论文试图解决什么问题？（按照引言逻辑）

**背景**：LLM Agent 用 RL 训练但依赖人工数据。

**痛点**：现有自进化框架受限于：
1. **模型固有能力**；
2. **单轮交互**——无法发展涉及工具使用或动态推理的复杂课程。

**缺口**：如何实现**多步、工具集成**的零数据自进化？

**本文贡献**：提出 Agent0，Curriculum Agent 与 Executor Agent 共进化 + 无缝工具集成。

## Q2: 有哪些相关研究？

- **零数据自博弈**：R-Zero（单轮推理）、Tool-R0（工具）；
- **课程学习**：自动难度调度；
- **工具集成推理**：Toolformer、ReAct；
- **多步推理**：长视野任务。

Agent0 的独特之处：**多步共进化 + 工具集成**，任务复杂度随工具能力提升而升级。

## Q3: 论文如何解决这个问题？（核心框架解释）

**核心机制：共生竞争的共进化 + 工具集成**

1. **Curriculum Agent（课程智能体）**：
   - 提出**越来越难的前沿任务**；
   - **为什么**：保持任务处于 Executor 能力边界，最大化信息增益。

2. **Executor Agent（执行智能体）**：
   - 学习解决这些任务；
   - **集成外部工具**增强问题解决能力。

3. **自我强化循环（Self-Reinforcing Cycle）**：
   - Executor 用工具变强 → 逼迫 Curriculum 构建**更复杂的、工具感知的任务** → Executor 面对更难任务再变强……
   - **为什么**：工具是"能力放大器"，使课程可以不断升级。

**为什么是"共生竞争"**：二者从同一基座初始化，既竞争（出题 vs 解题）又共生（共同进步）。

**多步的意义**：相比单轮问答，多步交互允许工具调用、动态推理，使课程更接近真实 Agent 任务。

## Q4: 论文使用的训练数据/结构细节/来源等详细信息（可复现目标）

- **数据**：零外部数据，自生成；
- **初始化**：同一基座 LLM（Qwen3-8B-Base）复制为两角色；
- **工具**：外部工具集（具体未详述）；
- **评测**：数学推理 + 通用推理基准；

## Q5: 论文做了哪些实验？

- **基座**：Qwen3-8B-Base；
- **数学推理**：**+18%**；
- **通用推理**：**+24%**；
- **意义**：零数据下大幅提升，且支持工具集成。

## Q6: 这篇论文的创新点和可以借鉴的地方

- **创新点**：多步共进化 + 工具集成；工具能力提升驱动课程升级的自我强化循环。
- **可借鉴**：
  1. **工具是课程升级的引擎**——工具越强，任务可以越复杂；
  2. 多步交互比单轮更接近真实 Agent 任务；
  3. 共生竞争的双角色设计。

## Q7: 这篇论文有哪些不足

- 工具集范围与泛化性未详述；
- 工具调用成本/延迟/安全未讨论；
- 自我强化循环可能失控（任务过难）或饱和（工具能力上限）；
- 8B 模型验证，更大规模未知。

## Q8: 提炼论文的一般技术和逻辑范式

**范式**：`Tool-Augmented Multi-Step Co-Evolution`

```
基座LLM → Curriculum Agent(出难题) + Executor Agent(工具解题)
   → 工具增强Executor → 逼迫Curriculum出更难工具感知任务
   → 自我强化循环 → 更强Agent
```

关键：**工具集成使课程可持续升级**，突破单轮推理的能力天花板。

## Q9: 针对这篇文章，思考有哪些值得做的研究话题

### 研究主题

- **上位类**：工具增强的零数据自进化
- **下位类**：课程升级机制、工具选择、多步推理
- **同位类**：R-Zero、Tool-R0、Agentic RL

### 数据类型
- 自生成多步任务、工具调用轨迹

### 研究设计
1. **课程稳定性**：研究如何防止课程失控（过难）或饱和；
2. **工具合成**：让 Agent 自己合成新工具（与 Tool-R0 呼应）；
3. **成本感知**：在多步工具使用中加入成本/延迟约束。
