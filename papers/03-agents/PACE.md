# PACE: Two-Timescale Self-Evolution for Small Language Model Agents

## 基本信息

- **作者**: Chen Ling 等
- **机构**: 亚马逊（Amazon）
- **发表会议**: arXiv 预印本（2026）
- **论文链接**: https://arxiv.org/abs/2605.23019
- **代码链接**: 未提供
- **关键词**: SLM Agent, Prompt Evolution, Control Logic, Two-Timescale, Held-Out Validation
- **摘要**: 在生产中部署语言模型智能体通常需要大量计算和人力来调优提示、解析器、验证器以及智能体管线的其他组件。自进化提供了一个有前景的替代方案，但大多数现有框架假设可以访问能够可靠诊断失败、提出修订并评判自身更新的前沿模型。我们研究**冻结的小语言模型（SLM）**在资源约束下能否作为有效的自进化智能体。我们提出 **PACE（Prompt And Control Logic Evolution）**，一个**两时间尺度框架**，协调低风险的提示精炼与高风险的控制逻辑更新。PACE 在固定控制逻辑下进化提示，直到提示级增益饱和，然后考虑通过 held-out 验证接受的受约束控制逻辑更新。在三个冻结的 SLM 骨干（4B 到 14B 参数）和四个受控基准上，PACE 在所有 12 个骨干-基准组合上取得最佳性能，相比 vanilla SLM 智能体提升高达 **+9.2% 相对改进**，相比更强的单模式进化基线提升高达 **+5.4% 相对改进**。τ-bench 案例研究进一步表明，PACE 相比 vanilla 和仅提示进化提升了多轮工具使用成功率。这些结果表明，可靠的 SLM 智能体自进化无需更新模型权重或依赖前沿模型教师，其关键收益不是任何单一的最终求解器模式，而是**自主、经验证的、任务适当推理策略的发现**。
- **TLDR 太长不想读**: PACE 研究"**小模型能否自进化**"。答案是可以，关键在**两时间尺度**：先做低风险的提示精炼（固定控制逻辑），饱和后再做高风险的控制逻辑更新（经 held-out 验证接受）。冻结 SLM（4B-14B）在 12 个骨干-基准组合全部最佳，最高 +9.2%。核心结论：**可靠的自进化不需要更新权重，也不需要前沿模型当老师**——关键是自主发现经验证的任务适配策略。

## Q1: 这篇论文试图解决什么问题？（按照引言逻辑）

**背景**：生产部署 Agent 需大量人力调优提示/解析器/验证器；自进化是替代方案。

**痛点**：现有自进化框架**假设能访问前沿模型**（用于诊断失败、提出修订、评判更新）；小模型（SLM）在资源约束下能否自进化未知。

**缺口**：冻结的 SLM 能否成为有效的自进化智能体？

**本文贡献**：提出 PACE 两时间尺度框架，证明 SLM 自进化可行且无需权重更新/前沿教师。

## Q2: 有哪些相关研究？

- **提示进化**：OPRO、EvoPrompt；
- **自进化 Agent**：ACE、RSEA（多假设前沿模型）；
- **小模型 Agent**：SLM 部署；
- **控制逻辑**：Agent 管线中的解析器/验证器；
- **两时间尺度优化**：快慢变量。

## Q3: 论文如何解决这个问题？（核心框架解释）

**核心机制：两时间尺度进化**

**尺度一：提示精炼（Prompt Refinement，低风险，快）**
- 在**固定控制逻辑**下进化提示；
- 持续直到**提示级增益饱和**；
- **为什么低风险**：改提示不会破坏 Agent 结构，安全。

**尺度二：控制逻辑更新（Control Logic Update，高风险，慢）**
- 提示饱和后，考虑**受约束的控制逻辑更新**（如解析器、验证器、流程）；
- 通过 **held-out 验证**接受；
- **为什么高风险**：改控制逻辑可能破坏整个管线，需谨慎验证。

**为什么两时间尺度**：
- 快变量（提示）先优化到饱和，成本低；
- 慢变量（控制逻辑）在必要时才动，且需验证；
- 这种分离避免同时改动多个组件导致的混乱。

**关键结论**：
- **无需更新模型权重**（冻结 SLM）；
- **无需前沿模型教师**；
- 关键收益不是某个固定的求解器模式，而是**自主发现经验证的任务适配推理策略**。

## Q4: 论文使用的训练数据/结构细节/来源等详细信息（可复现目标）

- **骨干**：三个冻结 SLM（4B–14B）；
- **基准**：四个受控基准 + τ-bench 案例研究；
- **验证**：held-out 验证接受控制逻辑更新；
- **可复现性**：论文未附公开代码。

## Q5: 论文做了哪些实验？

- **规模**：12 个骨干-基准组合（3 骨干 × 4 基准）；
- **结果**：PACE **全部最佳**；
- **提升**：相比 vanilla SLM **+9.2%** 相对；相比单模式进化基线 **+5.4%** 相对；
- **τ-bench**：多轮工具使用成功率提升。

## Q6: 这篇论文的创新点和可以借鉴的地方

- **创新点**：两时间尺度进化（提示 vs 控制逻辑）；证明冻结 SLM 可自进化。
- **可借鉴**：
  1. **快慢分离**——先优化低风险变量，再动高风险变量；
  2. **held-out 验证**接受高风险更新；
  3. 自进化不需要大模型/前沿教师——资源受限场景也可行。

## Q7: 这篇论文有哪些不足

- 两时间尺度的切换判据（何时算"饱和"）需调参；
- 控制逻辑更新的受约束范围有限；
- SLM 的能力天花板仍限制进化上限；
- 主要在受控基准，真实生产环境验证不足。

## Q8: 提炼论文的一般技术和逻辑范式

**范式**：`Two-Timescale Evolution (Fast Prompt + Slow Logic)`

```
固定控制逻辑 → 提示进化到饱和(快,低风险)
   → 受约束控制逻辑更新(慢,高风险,held-out验证) → 更优Agent
```

核心：**按风险分层进化**——低风险快改，高风险慢改且验证。
