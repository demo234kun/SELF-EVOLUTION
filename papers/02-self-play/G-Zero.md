# G-Zero: Self-Play for Open-Ended Generation from Zero Data

## 基本信息

- **作者**: Chengsong Huang 等
- **机构**: 香港大学（HKU）、字节跳动等
- **发表会议**: arXiv 预印本（2026）
- **论文链接**: https://arxiv.org/abs/2605.09959
- **代码链接**: 未提供
- **关键词**: Verifier-Free, Open-Ended Generation, Hint-δ Intrinsic Reward, GRPO, DPO, Co-Evolution
- **摘要**: 自进化 LLM 在可验证领域表现出色，但在开放式任务中挣扎，因为依赖代理 LLM 评判者会引入能力瓶颈和奖励黑客（reward hacking）。为克服这一点，我们提出 **G-Zero**，一个**无验证器（verifier-free）、共进化的框架**，用于自主自我改进。我们的核心创新是 **Hint-δ**，一种内在奖励，量化一个 Generator 模型的**无辅助响应**与其**条件于自生成提示（hint）的响应**之间的**预测偏移**。利用这一信号，一个 Proposer 模型通过 GRPO 训练，通过合成具有挑战性的查询和信息性提示来持续瞄准 Generator 的盲点。Generator 则通过 DPO 同时优化，以内化这些提示引导的改进。理论上，我们证明了 G-Zero 一个理想化标准 DPO 版本的 best-iterate 次优性保证，前提是 Proposer 诱导足够的探索覆盖且数据过滤保持伪标签分数噪声较低。通过完全从内部分布动力学中推导监督，G-Zero 绕过了外部评判者的能力上限，为跨不可验证领域的持续 LLM 自进化提供了可扩展、稳健的路径。
- **TLDR 太长不想读**: G-Zero 解决了"自我进化只能用于可验证领域"的难题。它的核心创新是 **Hint-δ 内在奖励**：测量模型"直接回答"与"看了提示后回答"之间的预测偏移，偏移越大说明该提示越有信息量。Proposer 用 GRPO 学习生成能最大化这个偏移的提示（即戳中 Generator 盲点），Generator 用 DPO 学习内化这些改进。完全不需要外部评判者，因此在开放生成任务上也能自进化。

## Q1: 这篇论文试图解决什么问题？（按照引言逻辑）

**背景**：自进化 LLM 在代码、数学等**可验证领域**表现优异。

**痛点**：在**开放式任务**（写作、对话）中，缺乏可验证信号，只能依赖代理 LLM 评判者，而后者引入**能力瓶颈**（评判者不够强）和**奖励黑客**（模型钻评判空子）。

**缺口**：能否设计一种**不依赖外部验证器**的内在奖励，使开放域也能自进化？

**本文贡献**：提出 G-Zero 框架与 Hint-δ 内在奖励，理论上证明收敛保证。

## Q2: 有哪些相关研究？

- **R-Zero**：可验证领域的零数据自博弈（本文的延伸对象）；
- **自奖励 LLM**：依赖 LLM-as-judge（本文要避免的）；
- **DPO / GRPO**：偏好优化与群体相对策略优化；
- **内在奖励**：好奇心驱动、预测误差驱动；
- **奖励黑客**：偏好模型被利用的经典问题。

## Q3: 论文如何解决这个问题？（核心框架解释）

**核心创新：Hint-δ 内在奖励**

定义：δ = Generator 的**无辅助响应**与**条件于自生成 hint 的响应**之间的**预测偏移（predictive shift）**。

- **直觉**：如果一个 hint 能显著改变 Generator 的回答分布，说明该 hint 揭示了 Generator 的"盲点"——有信息量；
- **反之**：如果加了 hint 回答几乎不变，说明该问题已在能力范围内，无信息增益。

**双模型共进化**：

1. **Proposer（提议者）**：
   - 合成挑战性查询 + 信息性 hint；
   - **训练方法**：**GRPO**（Group Relative Policy Optimization，群体相对策略优化）——通过组内相对比较估计优势，无需 critic 模型；
   - **目标**：最大化 Hint-δ，即持续瞄准 Generator 盲点。

2. **Generator（生成者）**：
   - **训练方法**：**DPO**（Direct Preference Optimization，直接偏好优化）——从偏好对直接优化策略，无需显式奖励模型；
   - **目标**：内化 hint 引导的改进。

**为什么用 GRPO + DPO**：GRPO 适合 Proposer（需要探索+相对比较），DPO 适合 Generator（需要稳定的偏好对齐）。二者配对形成共进化闭环。

**理论保证**：作者证明理想化 DPO 版本的 **best-iterate 次优性保证**（best-iterate suboptimality guarantee），条件为：(1) Proposer 诱导充分探索覆盖；(2) 数据过滤保持伪标签噪声低。

## Q4: 论文使用的训练数据/结构细节/来源等详细信息（可复现目标）

- **数据**：零外部数据，全部自生成；
- **组件**：Proposer（GRPO 训练）+ Generator（DPO 训练）；
- **关键机制**：Hint-δ 计算（两次前向的分布差异）、数据过滤（控制伪标签噪声）；
- **可复现性**：论文未附公开代码；复现需实现 Hint-δ 估计与双模型交替训练。

- 在**开放式生成**任务上验证（摘要未列具体基准数值）；
- 理论部分：证明 best-iterate 次优性保证；

## Q6: 这篇论文的创新点和可以借鉴的地方

- **创新点**：Hint-δ 内在奖励——把"预测偏移"转化为无验证器的自监督信号；GRPO+DPO 双模型共进化；理论收敛保证。
- **可借鉴**：
  1. "条件化响应差异"可作为通用内在奖励来源；
  2. 用 GRPO 做探索、DPO 做内化的分工模式；
  3. 数据过滤控制伪标签噪声，是稳定训练的关键。

## Q7: 这篇论文有哪些不足

- Hint-δ 依赖两次前向计算，**算力开销**较高；
- 理论保证基于理想化假设（充分探索覆盖），实际满足程度未知；
- 开放域评测本身主观，提升难以客观度量；
- 缺乏与强基线（如 RLHF 模型）的大规模对比。

## Q8: 提炼论文的一般技术和逻辑范式

**范式**：`Intrinsic-Reward Self-Play for Unverifiable Domains`

```
Proposer(GRPO) → 生成 hint → 计算 Hint-δ(预测偏移) → 作为内在奖励
Generator(DPO) ← 内化 hint 改进
   → 共进化，绕过外部 judge
```

这是对"验证层级"理论的重要补充：**当没有强验证信号时，用内部分布动力学构造信号**。

### 研究设计
1. **内在奖励对比**：系统比较 Hint-δ 与其他内在奖励（熵、预测误差）的效果；

3. **开放域基准**：构建能客观度量开放生成自进化的评测集。
