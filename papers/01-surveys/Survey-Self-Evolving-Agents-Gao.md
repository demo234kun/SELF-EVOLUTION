# A Survey of Self-Evolving Agents: On Path to Artificial Super Intelligence

## 基本信息

- **作者**: Huan-ang Gao 等
- **机构**: 清华大学、北京大学等（多机构合作）
- **发表会议**: arXiv 预印本（2025）
- **论文链接**: https://arxiv.org/abs/2507.21046
- **代码链接**: 未提供（综述论文）
- **关键词**: Self-Evolving Agents, LLM, Continual Learning, Artificial Super Intelligence, What-When-How
- **摘要**: 大语言模型（LLM）在各类任务上展现出卓越能力，但本质上是静态的，无法根据新任务、演变的知识领域或动态交互环境调整其内部参数。随着 LLM 越来越多地部署在开放式交互环境中，这种静态特性已成为关键瓶颈，亟需能够实时自适应推理、行动和演化的智能体。从"扩展静态模型"到"开发自进化智能体"的范式转变，激发了大量关于持续学习与自适应架构和方法的研究。本综述提供了首个系统且全面的自进化智能体综述，围绕三个基础维度组织该领域：**进化什么（what）、何时进化（when）、如何进化（how）**。我们考察了智能体组件（如模型、记忆、工具、架构）的进化机制，按阶段（如测试时内、测试时间外）对自适应方法分类，并分析指导进化自适应的算法与架构设计（如标量奖励、文本反馈、单智能体与多智能体系统）。此外，我们分析了面向自进化智能体的评测指标与基准，强调了编码、教育、医疗等领域的应用，并指出了安全性、可扩展性和共同进化动力学方面的关键挑战与研究方向。
- **TLDR 太长不想读**: 这是自进化 Agent 领域的第一篇系统综述，提出"what/when/how"三维分类框架。它把散落的研究统一到一个分析框架下：进化对象（模型参数、记忆、工具、架构）、进化时机（测试时内 vs 测试时间外）、进化驱动信号（标量奖励 vs 文本反馈）。文章还整理了评测基准、应用场景与安全挑战，是进入该领域必读的路线图。

## Q1: 这篇论文试图解决什么问题？（按照引言逻辑）

**背景**：LLM 已成为通用任务求解器，但其参数在部署后固定不变。真实世界任务要求模型能持续吸收新知识、适应新环境。

**痛点**：静态模型在开放式、交互式环境中表现受限——无法从交互经验中学习，无法适应演变的知识域。

**缺口**：虽然已有大量关于"自进化智能体"的零散工作（记忆更新、提示优化、工具合成、多智能体协作等），但**缺乏统一的分类框架**来理解这些方法之间的关系、差异与互补性。

**本文贡献**：
1. 提出首个系统综述，用 **what/when/how** 三维度统一组织该领域；
2. 系统分类智能体各组件的进化机制；
3. 梳理评测指标与基准，指出应用领域；
4. 指出安全、可扩展性、共同进化动力学等关键挑战。

## Q2: 有哪些相关研究？

- **元学习（Meta-Learning）**：学习如何学习，但受限于人工设计搜索空间。
- **持续学习（Continual Learning）**：避免灾难性遗忘，但多针对固定任务序列。
- **提示工程 / 上下文学习**：无需权重更新，但难以持久化积累。
- **多智能体系统**：涌现集体智能，但错误传播难以归因。
- **Gödel Machine / 自指系统**：理论上的自改进，但实践中不可证明。
- **自进化 Agent 系列工作**：R-Zero、EvolveR、Agent0 等（见本知识库其他论文）。

本综述的价值在于把这些分散脉络统一到同一坐标系。

## Q3: 论文如何解决这个问题？（核心框架解释）

本综述提出三维分类框架（**What-When-How**），这是理解全文的钥匙：

1. **What to evolve（进化什么）**——智能体的哪些组件可进化：
   - **模型（Model）**：参数微调、RL 训练；
   - **记忆（Memory）**：经验积累、检索、巩固；
   - **工具（Tools）**：自动合成新工具/API；
   - **架构（Architecture）**：提示、工作流、多智能体拓扑。

2. **When to evolve（何时进化）**——进化发生的时间尺度：
   - **测试时内（Intra-test-time）**：单次任务执行中实时调整（如 Reflexion 式反思）；
   - **测试时间外（Inter-test-time）**：跨任务迭代中离线进化（如 RL 训练、经验蒸馏）。

3. **How to evolve（如何进化）**——驱动进化的信号与算法：
   - **标量奖励（Scalar rewards）**：RL 式数值反馈；
   - **文本反馈（Textual feedback）**：自然语言批评/反思；
   - **单智能体 vs 多智能体**：自反思 vs 角色分工共进化。

**为什么用这个框架**：因为现有方法命名混乱（self-refine/self-reward/self-play/self-evolve 混用），需要区分"改进什么、何时改进、靠什么信号改进"。

## Q4: 论文使用的训练数据/结构细节/来源等详细信息

作为综述论文，本文**不涉及新训练**。其"数据"是已发表文献：作者系统检索并筛选了自进化 Agent 相关工作，按上述三维框架归类。读者若想复现某一类方法，应回溯到被综述的原始论文。

## Q5: 论文做了哪些实验？

综述论文不设新实验。其"实验"体现为**文献组织与对比分析**：作者将不同方法映射到三维框架中，比较其进化对象、时机与信号，并汇总各方法的评测基准（如 SWE-bench、ALFWorld、GAIA、WebArena 等）与报告结果。

## Q6: 这篇论文的创新点和可以借鉴的地方

- **创新点**：首个 What-When-How 三维分类法，填补了领域缺乏统一框架的空白。
- **可借鉴**：
  1. 用"进化对象/时机/信号"三轴定位任何一篇自进化论文；
  2. 指出组件间协同（模型+记忆+工具+架构联合进化）是未来方向；
  3. 强调评测需要专门的、能反映"进化能力"的基准，而非静态任务分数。

## Q7: 这篇论文有哪些不足

- 综述的时效性受限——该领域迭代极快，2026 年后大量新工作未纳入；
- 三维框架虽清晰，但对方法间的**因果依赖**（如记忆进化如何影响模型进化）分析较浅；
- 对安全与治理的讨论偏宏观，缺乏可操作的评测协议。

## Q8: 提炼论文的一般技术和逻辑范式

**核心范式**：自进化 = 一个闭环反馈系统，其状态是智能体（模型/记忆/工具/架构），其动力学由"评测信号"驱动。

```
任务交互 → 产生轨迹/反馈 → 提取改进信号 → 更新智能体组件 → 更强智能体 → 更难任务
```

这一范式贯穿全知识库的论文：无论 R-Zero 的 Challenger-Solver、ACE 的上下文进化，还是 DGM 的代码自修改，都是这个闭环的特例。

## Q9: 针对这篇文章，思考有哪些值得做的研究话题

### 研究主题

- **上位类**：通用自进化智能体架构（Continual Agentic Intelligence）
- **下位类**：记忆进化、工具合成、架构搜索、多智能体拓扑进化
- **同位类**：元学习、神经架构搜索、AutoML、开放-endedness 研究

### 数据类型
- 交互轨迹（trajectories）、环境反馈、评测基准（SWE-bench/ALFWorld/GAIA）

### 研究设计
1. **组件协同进化**：设计模型+记忆+工具联合进化的算法，验证是否优于单组件进化；
2. **进化能力基准**：构建能度量"跨任务持续改进"而非单任务分数的基准；
3. **安全-能力权衡**：研究进化过程中能力提升与安全对齐退化之间的动态关系（与 Misevolution 论文呼应）。
